## Budgets and evidence

The residency budget is 192 MiB of estimated RGBA GPU texture storage. Decoded backing images can approximately double that; transient browser decode buffers, compressed IndexedDB blobs, non-photo scene assets and driver overhead are additional. These are explicit application residency limits, not a promise of total browser RSS. A detail texture has a maximum 4096px edge (at most 64 MiB RGBA); only requested originals are read/decoded. Twenty-four distinct 2100×2100 imported images exercise repeated cache eviction; the observed ending cache was 190,840,832 bytes (35 textures), below the 201,326,592-byte budget.

`before/` and `after/` contain real Chrome/WebGL traces, video, samples and endpoint captures. The study imports 24 distinct 2400px crops generated from five repository photographs through the native chooser. Every resulting file/source is distinct, but this is a controlled loading study, not 24 independently photographed scenes. Three rapid Next inputs from frame 5 previously stopped at frame 6; afterward they reach frame 8. Initial measurements showed 32 sampled frames with asset work in progress before versus 13 after; this metric includes background prefetch and does not by itself measure blank frames. Median frame intervals remained about 83.3/83.4ms; p95 intervals were 133.3/116.7ms. The final measurements use Chrome 152.0.7977.82, ANGLE/Vulkan SwiftShader, an AMD EPYC 9575F host with 64 logical CPUs, and a 1280×800 viewport. The renderer reports an 8192px maximum texture edge; the application independently caps detail at 4096px. See `hardware.json` and `navigation-comparison.json`. No desktop-GPU speedup is claimed. The browser cache test additionally verifies the same actual texture IDs remain resident across a strip boundary.

The high-resolution test imports a generated 3072×2048 PNG with three-pixel alternating bars. Real rendered loupe samples show mean neighboring-pixel contrast 31.1176 using the original tier versus 23.886 using the 2048px derivative (about 30% more contrast). Its gate requires at least 3% improvement. The original tier reports 3072px, a forced decode failure keeps 2048px, and Retry detail restores the original tier. See `detail-comparison.json` and `07-detail-3072.png`. This is a controlled resolution target, not an enhancement of small originals.

`photographic-review/` contains library, import steps, full composition, rotation and final crop captures using the original repository photographs, plus a recording and page-error report. New browser tests cover staged import, append duplicate resolution, rejected/cancelled append, editing cancellation, crop geometry, long names, keyboard menu focus, reload, retargeting, stable texture IDs, focus and memory. Existing M12 tests still cover all formats, crop-edge pixels/rotation, EXIF normalization, quota failure, no uploads, browser restart and repeated URL release. The M12 library and panel-test selectors now follow the staged flow and selected-frame actions; no image/storage assertions were removed.
