# Darkroom Film Viewer — Implementation Plan

## Goal

Build a desktop web experience in which a user explores a realistic 3D darkroom, approaches an illuminated viewing table, and examines film with a loupe and stock-appropriate negative/positive views. The original experience contains one five-frame 35mm strip; M11 expands inspection to a 36-frame roll arranged as six strips of six. M12 adds a browser-local library of imported 35mm and 120 rolls. M13 adds full-angle look-around from a fixed standing position, independent room-light controls, and a room designed to be viewed in every direction.

The photographs and core interaction take priority over environmental detail. A milestone is complete only after its automated gate passes **and a human accepts the result**.

M14 improves the accepted M11/M12 film-viewing experience: continuous frame navigation, a polished roll library and import flow, explicit crop review, focus mode, clearer navigation context, incremental draft imports, and sharper on-demand inspection.

M15 extends the web experience to iPhone and iPad with touch-specific navigation, responsive layouts, usable mobile import/crop review, and bounded rendering costs. Implementation was authorized after the user's explicit acceptance of M1–M14 on 2026-09-11; M15 was accepted on 2026-09-13 UTC by the user's instruction to mark all prior milestones done.

M16 redesigns table viewing around Overview and Focus, with distinct desktop, iPad and phone interactions. Focus presents the selected image and its film border at a comfortable scale with visible space around them, rather than maximizing the image to the viewport. M16 is implemented in the main checkout and Awaiting human review. Its latest production build and 177 integration tests passed; 77/78 browser tests passed, with one intermittent loupe failure that passed twice in isolated rechecks. Human acceptance remains pending.

M17 implements the agreed three-state physical loupe: Inactivated → Activated → Inspection. The user authorized implementation on 2026-09-14 and explicitly disabled scroll/pinch zoom in Inspection while retaining movement. The production build, 184 integration tests and 24 M16/M17 browser tests passed; status is Awaiting human review. Review notes: `artifacts/m17-candidates/REVIEW.md`. This is the current milestone.

## Confirmed decisions

- Stack: React, TypeScript, Vite, Three.js, React Three Fiber, and Drei.
- M1–M14 target desktop Chrome/WebGL. M15 adds iPhone/iPad Safari and touch interactions while preserving desktop controls.
- Preserve the five existing source photos and baseline fixture. M11 adds support for 36 frames on six strips without placing numbers or selection badges over photographs. The default negative stock starts in negative view; M9 adds stock selection and positive-only reversal film.
- The loupe must visibly enlarge the detail underneath it.
- For negative stocks, a control switches all frames between negative and positive preview. Reversal stocks are positive-only.
- The final room should use plausible scale, PBR materials, local/CC0 assets, and restrained lighting effects.
- Runtime assets must be local. Do not deploy or publish.
- M12 stores imported rolls only in the current browser, with no server upload, account, or cross-device synchronization. Film format choices are 35mm and 120; 120 additionally specifies 6×4.5, 6×6, 6×7, or 6×9 image format.
- M13 uses one fixed standing position in room mode. The user explicitly chose looking around in place over orbiting around the table; there is no walking. Room brightness must be smoothly adjustable independently of the viewing-table light. M13 implementation and visual review were accepted on 2026-09-11.
- M15 was requested on 2026-09-11 for both iPhone and iPad, including redesigned gestures and UI layouts rather than emulated mouse controls. The user does not require HEIC/HEIF originals and asked about conversion on the phone. Keep JPEG/PNG as the stored import contract; the proposed mobile flow below uses system/native conversion where available, without adding a general HEIC decoder or storing HEIC originals.
- M16 was requested after the table-mode design discussion: Overview provides roll-wide exploration; Focus zooms toward the selected frame on the same table, retains neighboring imagery, minimizes UI, retains access to settings, and adapts interactions separately for desktop, iPad and phone. The user's explicit framing correction requires the image, film border, and surrounding breathing room to remain visible. Do not interpret Focus as edge-to-edge image fitting or omit the film border. Detailed layout and gesture choices below are the implementation design direction, subject to experiential review.

## Product flow

M14 preserves the room/inspection hierarchy and replaces the import presentation with `Photographs → Roll details → Review → Save and open`. Review includes an enlarged crop inspector for both new and existing rolls. Frame navigation can be retargeted while moving; camera movement and texture readiness are coordinated without clearing resident images. A reversible Focus mode hides secondary inspection controls while keeping navigation, frame position, and an explicit exit available.

```text
room --select table--> inspect --Back/Escape--> room
                         ├── negative <-> positive
                         └── loupe resting <-> active
```

Keep this state explicit in a reducer or small state machine. Prevent overlapping camera transitions and ensure returning to the room restores a valid camera pose.

M9 adds a whole-strip stock selector. The negative/positive branch above applies only to negative stocks; E100 always stays positive.

M11 extends inspect mode to `whole roll / strip / frame` camera framing levels. Room approach enters whole-roll view; a frame can be opened directly from any inspection level. Escape steps from frame to its strip, strip to whole roll, and whole roll to room. The existing explicit Return to Room control remains a direct exit. Stock, view mode, and brightness apply to the entire roll.

M12 adds `Rolls → New roll → choose photos → film details → review order/orientation → save and open`. Cancel returns to the existing roll without modifying it. Selecting a saved library item opens that roll, restoring its last valid inspection state. A new roll starts in whole-roll view with the selected stock's default allowed mode. Library/import dialogs own focus and keyboard input while open.

M13 changes only room exploration: drag to look around from a fixed eye position; use Face table to restore the default direction, or Approach Table from any direction to inspect. Return to Room restores the direction saved before approach. Room lights have their own switch and continuous dimmer. Inspection navigation, the table dimmer, and stock/view/loupe controls retain their responsibilities.

M15 keeps this hierarchy and adds the touch interaction contract below. A gesture has one owner: scene navigation, loupe, crop editor, or a DOM control. Moving through a scrollable UI must never also move the camera.

M16 supersedes the earlier table inspection hierarchy when implemented: `Overview → open frame → Focus → Overview`. Strip framing becomes an Overview zoom convenience rather than a third user-facing mode. Back/Escape closes an open settings panel first; otherwise it returns Focus to the saved Overview view, and only a subsequent action from Overview returns to the room. Existing M11/M14/M15 descriptions remain historical requirements until M16 replaces the affected behavior. M16 changes camera framing, not the accepted M12 crop-to-fill mapping inside the film aperture.

## Mandatory milestone gate

For every milestone:

1. Implement only that milestone and preserve all previously accepted behavior.
2. Run its named `npm run validate:mN` command against a production build.
3. The gate must include the current milestone and all existing regression integration and E2E suites. M9, M10, M11, and M13 are independently executable: an absent sibling suite is not a skipped test, and no placeholder suite is required. Run all sibling suites that are present.
4. Required tests must have zero failures and zero skips. Do not weaken assertions, mock WebGL in E2E, hide console errors, or update screenshots merely to make the gate pass.
5. Prepare the review evidence: exact command/result, local preview instructions, candidate screenshots and a short interaction recording, browser/viewport, and known limitations.
6. Set the milestone status to **Awaiting human review** and stop. Do not start another milestone in the same assignment unless the user explicitly approves or previously requested autonomous continuation. Exception to numeric ordering: the user may assign M9, M10, M11, or M13 independently, including concurrently; none requires the others' implementation or approval. M14 may be assigned before M13 once M11/M12 are integrated; run all present suites, without a placeholder for an absent M13 suite.
7. Only after approval: mark the milestone checkbox complete, record approval and commit evidence, and promote accepted candidate screenshots to regression baselines.

Vitest is used for integration tests. Playwright is used for E2E tests in real desktop Chrome with real WebGL, actual local assets, and normal pointer/keyboard input. Integration tests prove modules cooperate; E2E tests prove the user-visible production app works. State attributes may aid diagnosis, but they cannot replace canvas or interaction assertions.
